# PostgreSQL sync development, rollout, and portability

Use [ADR 0021](../adr/0021-portable-postgresql-sync.md) for accepted behavior. Financial/authentication contents never belong in logs, migration output, analytics, or committed fixtures. Use synthetic data and temporary confirmed Cognito users with notifications suppressed for endpoint checks.

## Local environment

```sh
pnpm install
pnpm run local:start
pnpm run db:migrate
pnpm run db:build-migrations
pnpm run local:sam
```

Docker PostgreSQL 18.6 exposes **55432** by default, avoiding a native PostgreSQL installation on 5432. Compose persists a dedicated PostgreSQL volume. The local-only database credential in `.env.example`/SAM is intentionally synthetic; it is never a cloud credential. Flyway runs on the Compose network and is pinned to `redgate/flyway:13.9.0`, with AMD64 emulation on ARM Macs. The Java migration package is built with Maven 3.9.11/Java 21 in Docker and includes Flyway 13.9.0, its PostgreSQL module, JDBC, SQL, and the CA bundle. No downloads occur in Lambda. Standard `pg` connection configuration is independent of AWS. Nonlocal database URLs or PGUSER/PGPASSWORD require PG_CA_FILE and verified TLS; AWS supplies DB_SECRET_ARN instead.

SAM uses host.docker.internal:55432 for PostgreSQL and the existing Cognito pool/client for authenticated local sync/voice. The `x-local-subject` test hook requires both local runtime and explicit ALLOW_LOCAL_SYNC_SUBJECT=1; it is off by default and never configured in AWS. Rebuild SAM before endpoint checks. Keep API/auth origins configured to the same development environment. EXPO_PUBLIC_SYNC_API_URL optionally overrides the endpoint; otherwise sync uses the configured voice backend root. Do not enable analytics for synthetic account/device tests.

Before mobile testing, inspect `adb devices` and `xcrun xctrace list devices`, prefer physical devices, use `pnpm run android`, and build the attached iPad with `pnpm run ios -- --device <UDID>`. Use `pnpm run start:all` and Expo's a/i/w shortcuts for one server. Native modules require a development client. The iOS Podfile plugin aligns dependency targets with the app's existing iOS 15.1 minimum for Xcode 27. On hosts with limited space, build with xcodebuild -derivedDataPath on another disk and install the resulting app using pnpm run ios -- --binary <app-path> --device <UDID> --no-bundler.

If Watchman stalls during an export, use `UNFANCY_USE_WATCHMAN=0 pnpm exec expo export --platform ios --output-dir <build-directory>` to select Metro's bundled Node crawler for that invocation. Normal builds retain Watchman. Do not stop a shared watcher or reset local financial storage to resolve build tooling problems.

## Migrations and checks

```sh
pnpm run typecheck
pnpm run lint
pnpm test
pnpm run test:integration
pnpm run test:contract
pnpm run local:build
```

SQL integration checks require `local:start`; TEST_DATABASE_URL can point to a dedicated PostgreSQL test instance. Flyway checks launch and remove disposable Docker databases, copy migrations into a temporary directory, verify repeat runs, checksum rejection, concurrent locks, transactional rollback, and restoring a dump into another vanilla PostgreSQL instance before continuing sync. Source migrations are never modified by these checks. Do not point synthetic integration tests at a real dataset/database.

SAM uses a Makefile to bundle handlers with the existing lockfile-resolved esbuild dependencies through `pnpm run local:build`. It copies only the SAM source directory, avoiding native build artifacts and a second npm dependency installation. `local:sam` invokes this build automatically.

V002 adds immutable request hashes for valid conflicted/rejected mutations as well as accepted mutations. Preserve this table when restoring; retries with altered contents fail even before acknowledgment.

Applied SQL files must never change. Add V002/V003 corrections after release. `validate` allows pending migrations but rejects checksum mismatches; `migrate` validates again and refuses unexpected nonempty schemas without history. `clean` is disabled. There is no automatic repair/baseline. Recover destructive mistakes using backups; use forward corrections for application rollback.

## Development fallback for low-quota accounts

This section records the fallback for a historical or future account limit of 10 simultaneous Lambda executions in us-east-1. The current dev account has a live limit of **1,000**, with 1,000 unreserved executions, so the deployment uses the normal **5/2/1 reservations**. AWS requires 100 executions to remain unreserved when assigning reservations. See [AWS reserved concurrency](https://docs.aws.amazon.com/lambda/latest/dg/configuration-concurrency.html).

If a future live quota cannot support reservations, development can explicitly use shared account concurrency for sync, rate API/cache, voice, and migrations. Select it with `DEV_LAMBDA_CONCURRENCY_MODE=shared pnpm run infra:deploy:dev`; direct CDK commands use `-c stage=dev -c devConcurrencyMode=shared`. The default remains reserved concurrency; use `DEV_LAMBDA_CONCURRENCY_MODE=reserved` (or omit it) for 5/2/1. Shared mode requires an unreserved pool limit of at least 10; that setting does not report currently free execution slots. Production rejects shared mode. V003 applies sync/cache login-role connection limits of 5/2, and credential provisioning preserves those limits. Recheck the live quota before selecting this fallback.

Preserve the one-connection-per-environment pool, verified TLS, private networking, and separate credentials. A limit of 10 active Lambda invocations does **not** guarantee only 10 PostgreSQL connections: idle connections can remain in warm/frozen environments. Role connection limits provide the additional database bound; reaching them may cause connection failures. The pool currently has a five-second connection timeout and 60-second idle timeout, but frozen Lambda environments can delay idle cleanup. Run migrations once, explicitly, before handler release and away from device/load tests; Flyway's database locking still applies without a Lambda reservation. Stop unrelated development traffic while checking two devices.

### Troubleshooting shared-quota contention

| Symptom | Check without exposing payloads | Response |
| --- | --- | --- |
| Sync, rates, or voice intermittently fails while several features run | Account and function `ConcurrentExecutions` and `Throttles`; API status counts and worker errors at the same time | Reduce simultaneous requests and pause unrelated tests. Retain pending edits and use bounded retry/Sync now after traffic drops. Do not reset records. |
| Rates fail during otherwise successful requests | Compare public rate and private cache throttles/errors: the public worker occupies a shared slot while awaiting the cache worker | Confirm a successful upstream result still returns during cache failure, or that stale fallback is visibly marked. An outage with neither upstream nor cached rates must remain an error. Avoid exercising rates and voice during sync load checks. |
| Connection attempts fail or become slow without Lambda throttling | RDS `DatabaseConnections`, CPU/freeable memory, numeric connection-latency metric, and role connection counts/limits | Distinguish role-limit exhaustion, retained idle connections, and database capacity. Wait for idle cleanup and reduce traffic; do not increase connection limits blindly or add more pool connections. |
| Migration invocation is throttled | Account concurrency and migration outcome; validate Flyway history | Quiesce test traffic and retry the explicit invocation after capacity is available. Require successful validation/migration before deploying schema-dependent handlers. Never clean, repair, or baseline to bypass the failure. |

In the historical 10-slot scenario, other workloads in the same account/region share the quota and may consume capacity. Shared fallback gives no per-function capacity guarantee; API throttling, if added, is only load smoothing rather than a hard database connection limit. Client pending data must survive transient failures and authentication failures must still pause retries. Use fixed error codes, timestamps, request IDs, aggregate metrics, and counts for diagnosis; never log SQL, parameters, row contents, financial data, or tokens. When inspecting PostgreSQL activity, aggregate by role/state without selecting query text.

The live quota check confirmed sufficient capacity for sync/cache/migration reservations of 5/2/1; the rollout uses reserved mode. Retain database connection protection and monitoring. The development exception does not authorize production release.

## Moving to another vanilla PostgreSQL host

Quiesce client requests and worker writes first. Retain pending client outboxes and pull cursors; do not reset devices or create a new cloud dataset. Take a consistent custom-format dump using a protected credential file/environment, never credentials in command-line URLs:

