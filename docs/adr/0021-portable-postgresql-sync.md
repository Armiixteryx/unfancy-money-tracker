# ADR 0021: Restore opt-in sync with portable PostgreSQL and Flyway

## Status

Accepted. Supersedes ADR 0015 and the sync suspension in ADR 0016. Updates ADRs 0001, 0003–0007, 0010–0011, 0017–0018, and 0020. Production deployment was explicitly authorized October 5, 2026 and retains the separate deployment gate; ADR 0014 continues to defer retail preview.

## Context

One personal Cognito login needs one cloud dataset that can sync across devices without replacing local persistence or introducing an ORM. The low-traffic portfolio service needs a predictable database baseline and a credible migration to another vanilla PostgreSQL host.

## Decision

Use RDS PostgreSQL **18.6**, pinned after checking `describe-db-engine-versions` in `us-east-1`, with `db.t3.micro` (x86), Single-AZ, 20 GiB gp3, encryption, and private networking. AWS rejected seven-day automated backup retention for the development account; the user approved one day for development, which the deployed dev database accepted. The owner approved one-day production automated backups on October 5, 2026 after AWS also rejected seven days for production. Do not disable backups if AWS rejects the one-day development setting. Docker uses the same patch. AWS does not offer `db.t4g.micro` for PostgreSQL 18.6 in `us-east-1`; `db.t3.micro` is the compatible micro instance and stays close to the original monthly estimate. Production deployment was authorized October 5, 2026. Provision the database in a separate stack before updating the existing service stack; keep Cognito, pool/client, API, and existing function construct identities.

Store datasets, categories, transactions, budgets, currency preferences, and exchange rates in normalized SQL tables. `NUMERIC` values cross the API as canonical strings; dates stay date-only. Retain immutable change history, deletion metadata, and content-hashed retry acknowledgments without TTL. Every accepted mutation locks its owned dataset row, updates domain tables, allocates revisions, appends history, and saves its acknowledgment inside one PostgreSQL transaction. Revisions, rather than device clocks, order commits. Device edit and server commit timestamps are separate. Pull is paginated; push never returns or advances a pull cursor.

New dataset, custom category, transaction, budget, and mutation IDs use UUIDv7. System categories use `${kind}-${defaultCategoryKey}` (for example `expense-food`), shared across datasets. Currency preferences are one singleton `currency` record per dataset and contain only base and selected currencies. Protected system identities and compound category references have SQL constraints/triggers; budgets have one row per dataset/category/month. Category reassignment, dependent changes, and deletion commit together. Reassignment that would collapse competing budgets fails without discarding either; resolve those budgets before deleting the category.

Use handwritten versioned SQL and **Flyway Community 13.9.0**, with the matching PostgreSQL module. Local/CI run its pinned Docker image with AMD64 emulation where needed. AWS runs a Java 21 Lambda built by pinned Maven tooling with Flyway, JDBC, SQL, service-loader metadata, and RDS CA certificates bundled. No runtime dependency downloads or NAT are needed. Validate before migrate, allow pending versioned migrations in validation, keep `clean` and automatic baseline disabled, and never repair checksums automatically. Applied migrations are immutable; corrections use new migrations. Forward corrections support application rollback; destructive mistakes require backup recovery.

Repositories take a plain `pg` pool and have no AWS dependency. The runtime adapter supports database URLs, standard PostgreSQL credential environment settings, configured CA certificates, or AWS Secrets Manager. Nonlocal connections require verified TLS. Each Node execution environment owns a pool with maximum one reusable connection. Reserved concurrency is five for sync, two for cache, and one for migration. Database connections, CPU, memory, worker errors/throttles, and a numeric-only connection-latency metric have alarms. SQL, row contents, parameters, provider bodies, and credentials are excluded from diagnostics. Query diagnostics are disabled. Local PostgreSQL and RDS suppress ordinary database error logs, which can include offending values despite statement logging being off, using `log_min_messages=fatal` and terse errors without detail/context. RDS retains PostgreSQL 18's disabled connection-logging engine default because its API rejects explicit empty/legacy-zero values. Operational failures are monitored through content-free application metrics and infrastructure alarms.

Sync and cache have separate privilege/login roles and separate Secrets Manager credentials. The migration Lambda has its own database credential and configures the application role passwords explicitly after migration. The private Secrets Manager endpoint provides credential access without NAT. The public rates Lambda retains internet access and invokes the private cache Lambda through IAM; the cache has no public URL or API route. Existing 24-hour freshness, stale fallback, and successful upstream responses during cache failure stay unchanged. This split avoids a NAT baseline; consolidate behind NAT when traffic, outbound requirements, or operational simplicity justify the cost.

Schema 8 retains the one shared encrypted MMKV/IndexedDB dataset and adds durable sync binding, cursor, revisions, outbox, conflicts, and last-sync time. Credentials remain in dedicated auth storage. Login enables voice independently; Settings separately enables sync with an upload notice. Empty cloud uploads directly. Existing cloud offers merge or explicitly confirmed replacement. Merge keeps distinct custom categories/transactions and exposes competing monthly budgets as manual conflicts. Replacement downloads and validates all pages before saving a replacement snapshot, preserving device-only language, theme, consent, and notice choices.

Successful local saves, launch, foreground, reconnect, and manual Sync now trigger sync; there is no polling/background requirement. Unsent edits coalesce against their original base revision. Submitted requests stay immutable until acknowledged; subsequent edits use separate mutation IDs. Authentication failure pauses automatic attempts; transient failures use bounded backoff. Manual resolution uses a new mutation ID against the observed cloud revision; intervening edits return another conflict. Logout retains local records and pending changes. The same login resumes. A different login requires a confirmed local reset. Local reset removes binding/outbox and leaves cloud records intact. Lifecycle epochs and abort signals invalidate stale sync and voice responses.

The development cutover starts fresh: remove the old DynamoDB tables after PostgreSQL migration and API switch, then explicitly confirm local reset on development installations. Never reset data during hydration. Schema-7 snapshots are backed up, retain financial records and historical UUIDs, and remap keyed system identities/references to slugs. Historical non-v7 records remain readable but require explicit development reset before upload/merge; replacement remains available after confirmation. Guest use is unaffected. Recovery artifacts remain preserved.

## Consequences

- The `db.t3.micro` plus 20 GiB gp3 baseline is approximately **$15.44/month** at 730 hours (AWS Price List on-demand: $0.018/hour plus $0.115/GB-month). This excludes the Secrets Manager endpoint, Lambda, logging, tax, and other infrastructure. The larger `db.t4g.small` alternative is approximately $25.66/month; its Graviton micro size is not orderable for this engine/version/region. Burstable-size estimates exclude any surplus CPU-credit charges; recheck orderability and pricing before future deployments.
- Development backup retention is explicitly one day under the approved recovery-window exception; the deployed dev database accepted it. Production also retains one day under the October 5, 2026 owner-approved account-plan exception. If AWS rejects one day in a future account, stop and choose an account-plan or retention option before retrying; never set zero automatically.
- The endpoint and two-function rate design are deliberate portfolio cost/complexity choices. Single-AZ has no standby failover.
- A dataset lock favors correctness at this traffic level; scale concurrency only with connection/capacity measurements.
- A development-only shared-concurrency fallback remains available for an account with a low Lambda quota. The current account's live limit is 1,000, so development uses reserved concurrency 5/2/1 by default. Shared mode omits per-function reservations and can throttle competing sync, rates, voice, or migration work; select it explicitly with `DEV_LAMBDA_CONCURRENCY_MODE=shared` (CDK `devConcurrencyMode=shared`). V003 and credential provisioning retain role limits of 5/2. See the [quota-fallback troubleshooting runbook](../development/postgresql-sync.md#development-fallback-for-low-quota-accounts) before enabling it.
- The database stack deploys and migrations run while existing services remain available. The service release removes DynamoDB and enables slug-capable voice before the schema-8 app release.
- Portability requires preserving IDs, revisions, history, tombstones, acknowledgments, and Flyway checksums; see the dump/restore runbook.

## Validation

Unit tests cover the durable outbox, save failure, in-flight edits, account lifecycle, replacement, merge, device preferences, and clocks. PostgreSQL integration tests cover ownership, references, protected categories, ordered concurrency, idempotency, pagination, tombstones, atomic reassignment, manual resolutions, and two independent client stores. Disposable Docker instances verify Flyway repeatability/checksums/locking/transactional rollback and dump/restore followed by continued sync. CDK assertions check networking, database settings, IAM, Cognito identities, and absent DynamoDB/NAT/proxy resources. Operational checks and their actual results belong in the development runbook.

Category deletion defers to the server for atomic dependent reassignment. If two monthly budgets would collide at Uncategorized, synchronization pauses for an explicit budget choice before deletion completes. Request identities remain immutable even for conflicted pushes and rejected resolutions; V002 remembers their content hashes without logging the contents.
